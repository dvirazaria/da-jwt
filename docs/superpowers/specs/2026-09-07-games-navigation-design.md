# משחקים וזרימת משחק פעיל — מסמך תכנון

## מטרה

להפוך את ״משחקים״ למסך הבית של עולם המשחקים, ולהפוך את ״שולחן״ ו״חישוב״ למסכים פנימיים של משחק פעיל, בלי לשכתב או לשכפל את לוגיקת הקופה הקיימת.

## מצב קיים

האפליקציה היא PWA חד־קובצי ב־`kupa-sgura.html`. המשתנה `mode` משמש היום גם כניווט הראשי וגם כבחירת הרינדור: `game`, `settle`, `profile`. הנתונים נשמרים ב־`state` ב־localStorage ומסתנכרנים במסמך Claude כאשר הסביבה תומכת בכך. אין כרגע phase נשמר למשחק, ואין מסך dashboard למשחקים.

## החלטה ארכיטקטונית

נוסיף state מינימלי מעל הרינדור הקיים:

- `state.phase`: אחד מ־`active`, `settlement`, `closed`.
- `appView`: אחד מ־`games`, `game`, `settle`, `profile`. הוא יחליף את `mode` כשם ולוגיקה, אך ישמור את אותם מסלולי רינדור עבור שולחן, חישוב ופרופיל.
- בנתונים ישנים ללא phase: משחק עם שחקנים יקבל `active`; state לדוגמה או state ללא שחקנים יקבל `closed`.
- בטעינה, `active` פותח את השולחן, `settlement` פותח את החישוב, ו־`closed`/דוגמה פותחים את dashboard של משחקים.

## Navigation ו־dashboard

סרגל הניווט הראשי יציג **משחקים** ו־**פרופיל** בלבד. אין יותר לשוניות ראשיות נפרדות ל״שולחן״ ול״חישוב״.

מסך משחקים יציג:

- משחק פעיל או משחק שנמצא ב־settlement, עם פעולה מתאימה: ״כנס לשולחן״ או ״המשך סגירה״.
- אזור קבוצות עם empty state וכפתור ״צור קבוצה״ במצב משני/לא פעיל, ללא מימוש קבוצות בשלב הזה.
- פעולה פעילה ״משחק ללא קבוצה״ ליצירת משחק חדש.
- כשאין משחק פעיל, לא תהיה כניסה אוטומטית לשולחן ולא יוצג כפתור כללי ״התחל משחק״.

יצירת משחק ללא קבוצה מאתחלת state חדש עם `phase: "active"`, game id חדש, players ריקים, והיסטוריה וחובות קיימים נשמרים.

## זרימת משחק

- `active`: הרינדור הקיים של השולחן נשאר מקור האמת לעריכת שחקנים, buy-ins, rebuys ופירוט כניסות.
- במסך השולחן יתווסף כפתור ״סיים משחק״ עם לחיצה ארוכה רציפה של שנייה. progress אופקי ממלא את הכפתור במהלך ההחזקה; שחרור מוקדם מנקה את ההתקדמות ולא משנה phase.
- השלמת ההחזקה משנה רק את `state.phase` ל־`settlement`, שומרת ומציגה את הרינדור הקיים של החישוב.
- במסך החישוב יתווסף כפתור משני ״חזור לעריכת המשחק״. הוא משנה את ה־phase ל־`active`, שומר ומציג שוב את אותו state של השולחן.
- ״סגור שולחן״ נשאר הפעולה הסופית הקיימת. רק היא בונה history/debts, מאפסת את המשחק הנוכחי ומגדירה `phase: "closed"`, ואז מציגה את dashboard של משחקים.
- כל מנגנון cashout, balance difference, force close, settlement status, transfers ו־debt records נשאר משותף ולא משוכפל.

## Persistence וסנכרון

`phase` ייכלל ב־`normalize`, `save`, `remoteBody` ו־`applyRemote`. Refresh או פתיחה מחודשת יבחרו את `appView` לפי ה־phase האחרון. סגירה סופית תשמור history/debts לפני המעבר ל־dashboard.

## בדיקות קבלה

- טעינה ללא משחק פעיל מציגה dashboard משחקים ולא שולחן ריק.
- ״משחק ללא קבוצה״ יוצר active game ונכנס לשולחן.
- לחיצה רגילה על ״סיים משחק״ אינה משנה phase; החזקה מלאה משנה ל־settlement.
- refresh ב־active חוזר לשולחן; refresh ב־settlement חוזר לחישוב.
- ״חזור לעריכת המשחק״ משמר players, buy-ins, entryLog, cashouts ו־settlement statuses.
- שינוי buy-in/rebuy אחרי חזרה מחושב מחדש בחישוב.
- סגירה סופית בלבד מוסיפה history/debts ומציגה dashboard; משחק closed אינו ניתן לעריכה רגילה.
- כל בדיקות הרגרסיה הקיימות של חובות, איזון, כניסות ותשלומים ממשיכות לעבור.
