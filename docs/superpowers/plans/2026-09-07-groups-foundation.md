## Task 0 audit — what exists today (read this before any task)

### Architecture
- One file: `kupa-sgura.html`. CSS lines ~3–500, HTML ~503–598, one JS IIFE ~600–2276.
- `index.html` and the cache name in `sw.js` are generated by `python3 build.py`. Never edit them by hand.
- Tests: `tests/*.test.cjs`, Node built-in runner. They slice the HTML source between two string
  markers (`sourceBetween(startMarker, endMarker)`) and run the slice in `vm` with a bare context.
  **Consequence:** pure domain functions must be contiguous, DOM-free, `state`-free, and start at
  column 2 with `  function name(` so a test can slice them. Wiring is asserted with regexes on the HTML.

### State (single source of truth, `state` object)
```
state = {
  example: bool,                 // demo data flag
  gameId, phase: "active"|"settlement"|"closed",
  players: [{ id, name, buyins:[n], entryLog:[{id,timestamp,amount,playerId,gameId}], cashout: ""|n }],
  settlementStatuses: { [settlementKey]: true },   // reversible "paid" toggles for the open game
  groupId: string|null, startedAt: ISO|null, updatedAt: ISO,
  history: [HistoryEntry],       // closed games, newest first, capped HISTORY_MAX
  debts: [Debt],                 // open/paid debts from closed games
}
HistoryEntry = { gameId, at, isBalanced, balanceDifference, transfers:[{id,from,to,amount,status}],
                 players:[{ id, name, entryLog, buyin, cashout, net }] }
Debt = { id, gameId, groupId, debtorUserId(=player.id), creditorUserId, debtorName, creditorName,
         amount, status:"open"|"paid", createdAt, gameDate, paidAt }
```
- `normalize(s)` (line ~728) is the only loader/migrator. `load()` → localStorage `poker-settle-v1`.
- `save()` is the only writer: sets `updatedAt`, writes localStorage, `scheduleRemoteSave()`.
- Remote sync (`remoteBody`, `applyRemote`, `initSync`) mirrors the whole state to a Claude
  artifact doc; only active inside claude.ai. `applyRemote` compares a fixed list of fields.
- **Identity:** `me` = a typed name (localStorage `poker-settle-me`). Not auth. Name matching is the
  identity rule everywhere (debts, profile, `knownNames()`).
- **Only one current game slot exists.** `state.players/phase/gameId` is *the* game; closed games
  move to `history`. There is no games collection.
- Sites that build a **new state object by hand** (and would drop any new collection):
  `markReal()` (~910), `startUngroupedGame()` (~1126), reset button (~2170). `finishCloseTable()`
  mutates in place (safe).

### Flows
- Add player: `addPlayer()` → immediate first buy-in (MIN_BUYIN 50). A player with 0 buy-ins cannot
  exist: "בטל אחרונה" on the last entry removes the player row entirely.
- Buy-in: `confirmBuyin()` → `addEntry()` keeps `buyins` and `entryLog` in sync.
- Finish game: 1s hold → `finishGame()` → `phase="settlement"`, view `settle`.
- Settlement: cashout inputs, `tableBalance()`, `settle()` greedy transfers, paid toggles.
- Close: `finishCloseTable()` → `buildHistoryEntry`, `buildDebtRecords`, `history.unshift`,
  new `gameId`, `phase="closed"`, view `games`.
- Views: `appView` ∈ `games|game|settle|profile`, `setAppView()`, `render()` re-renders everything;
  `renderDerived()` refreshes stat line, transfers, close buttons; `renderProfile()`; `renderGamesDashboard()`.
- Dashboard adapters: `getActiveGameSummaries(state)` (0..1 items), `getGroupSummaries()` → `[]`.
  `renderGroupCard(group, actions)` already renders name/avatar/memberCount/hasActiveGame + expand.
- Profile: `renderProfile()` with tabs `balance|debts`, uses `me` name matching.

### Persistence decision (E)
Groups, members, invites, friendships live **inside the same persisted `state` document** (same
localStorage key, same remote doc). They are loaded in `normalize()`, saved by `save()`, mirrored by
`remoteBody()`. No new localStorage keys. No second store. The UI reads only through adapters.

### Identity decision (pre-backend)
- `ParticipantRef = { userId: null, guestId: string, displayName: string }`. `userId` is always
  `null` until a backend exists; nothing may fabricate one.
- `guestId` is the stable local identity. `resolveGuestId(state, displayName)` reuses the guestId of
  an existing group member or history participant with the same displayName, else creates one — so
  the same person keeps one id across groups on this device, consistent with the app's existing
  "name is the identity key" rule.
- "Who am I" inside a group = the member whose `displayName === me` (`findMyMembership`). Documented
  limitation; replaced by `userId === session.userId` later.

### Leaderboard eligibility decision (deviation, documented)
Spec: unlinked guests are excluded from the leaderboard. Pre-backend nobody is linked, which would
make every leaderboard empty and Task 12 unverifiable. Rule adopted, in ONE function
`isLeaderboardEligible(participant, members)`: a participant is eligible when their identity
(`userId` or `guestId`) matches a GroupMember record of that group (active or former). Ad-hoc game
guests who are not members are excluded. When accounts arrive, this function tightens to
`userId != null` without touching the UI.

### Single active game decision (documented limitation)
The engine has one current-game slot. A group can therefore have at most one open game (spec ✔),
and additionally the whole device can have only one open game at a time (pre-existing limitation).
`canStartGroupGame()` reports `another-game-open` in that case and the UI explains it. The backend
will own a `games` table with per-group open-game uniqueness; the engine is not duplicated now.

### Things intentionally left for backend
Real accounts, friend request delivery, invite redemption/joining, remote membership, group image
hosting, concurrent games across groups, guest→account merge.

## Global Constraints (bind every task)

1. Only `kupa-sgura.html` is edited for runtime. `index.html`/`sw.js` only via `python3 build.py`
   (do NOT run build.py inside tasks; the controller builds at release).
2. Do not create new files for runtime code. No React/Vite. No new localStorage keys.
3. Keep all existing behavior: buy-in/rebuy/entry log, finish-game hold, settlement, balanced/forced
   close, paid toggles, debts, profile, theme, login, sync. Existing 37 tests must keep passing.
4. Pure domain functions: DOM-free, `state`-free (take arguments), placed contiguously inside the
   marked section named by the task, each starting at column 2 with `  function name(`.
5. Derived data is computed by adapters, never stored (leaderboard, winners, gameCount, lastGame).
6. No fake backend, no fake multi-user, no hardcoded production-like groups/users.
7. `save()` is the only writer. Every new collection flows through `normalize()` and `remoteBody()`.
8. Design system per `DESIGN.md`: flat rows, hairline `--line` separators, `--accent` only chromatic
   accent, `--bad` only for warnings/loss, Heebo, ≥44px touch targets, both themes, reduced-motion.
   No `alert`/`confirm`/form submit — inline two-step confirm patterns only.
9. Money is integer ILS (`wholeMoney`). Net = cashout − sum(buyins).
10. Group UI must never display another person's exact net/P&L or debts.
11. Tests: extend `tests/*.test.cjs` with the vm-slice pattern; run `node --test tests/*.test.cjs`
    and `git diff --check` before every commit. Commit on `main` with a conventional subject.
12. Hebrew microcopy, short and direct. RTL.
13. **Motion is mandatory wherever something moves or appears.** Every new button has a press
    state (`transform: scale(.92)` ~.12s) and transitions on background/color/border (~.2s). Every
    panel/expansion opens with the grid `0fr → 1fr` collapse pattern (~.28s) and its arrow/plus
    rotates. Every new screen or overlay (group page, settings overlays, join notice, participant
    picker) enters with fade + `translateY(6px)` rise (~.3s), and list rows stagger in (40-60ms per
    row, `.anim` pattern). Armed/danger states animate their color change. Feedback text
    ("הועתק ✓", tags appearing) fades in. Checkbox/selection toggles animate the check. All of it is
    disabled under `prefers-reduced-motion: reduce` (the existing global rule covers it — do not
    add per-element overrides that bypass it). Reuse existing keyframes/classes (`.anim`, `.load-in`,
    `.pmenu` transition, `.chip` stagger, `.pulse`) before inventing new ones; new keyframes go next
    to the existing ones.

## Task 1: Player exit mid-game ("יציאה")

**Goal 1:** a player can exit early with a cashout; they are marked `exited`, cannot rebuy, are not
asked for cashout again in settlement, and settlement/P&L/transfers/close work unchanged.

### Data
- Player gains `status: "active" | "exited"` and `exitedAt: ISO | null`. `normalize()` defaults
  `status` to `"active"` and `exitedAt` to `null` for legacy players. `addPlayer()` creates
  `status:"active", exitedAt:null`.
- Exit stores `cashout` (integer ≥ 0) on the existing `cashout` field — no second field.
- `buildHistoryEntry()` copies `status` and `exitedAt` into history players.

### Pure functions — section `  // ---------- player exit (pure) ----------` placed right after
`settle()` and before `function el(`:
```
function exitPlayer(player, cashout, at)      // sets status/exitedAt/cashout; returns false if already exited or invalid
function updateExitCashout(player, cashout)   // only when status==="exited"; integer ≥ 0
function activePlayers(players)               // status !== "exited"
function exitedPlayers(players)
function isExited(player)
```
`tableBalance()` and `settle()` are unchanged (they already count every player's cashout).

### UI (game view, per player row)
- Active player: existing plus button. Add a small text action "יציאה" (class `exit-toggle`,
  styled like `.entry-toggle`) next to "פירוט כניסות" in `.player-heading`.
- Clicking "יציאה" opens an inline capsule row inside the player row (reuse `.pmenu/.pmenu-in`
  markup and transition): a number input `inputmode=decimal` placeholder "צ'יפים ביציאה" and a button
  "אשר יציאה" (two-step: input then button; Enter confirms). Invalid → `shakeEl`. Confirm → `exitPlayer`,
  `save()`, `render()`. Only one of buy-in menu / exit panel is open per row (`openMenu` vs a new
  UI-only `exitOpen` variable holding the player name).
- Exited player row: no plus button. `.pmeta` shows `<b>total</b> · N כניסות`, then a quiet tag
  "יצא · ₪X" (class `exit-tag`, `--dim`, 12px) and a text action "עריכה" that reopens the same panel
  prefilled to change the amount (`updateExitCashout`). Row gets class `prow exited` with reduced
  opacity for the name (0.55), not hidden.
- Stat line in game view: `N שחקנים` → when any exited: `N שחקנים · M יצאו`.
- Settlement view: exited player's cashout input is prefilled and stays editable (same field);
  row shows the "יצא" tag next to the name so nobody re-asks them.
- `markReal()` guard on all new click handlers (same as plus button).
- Undo last entry of an exited player: keep existing behavior but do not remove exited status;
  if buy-ins reach 0 the player is removed exactly as today (they had no money in).

### Tests (`tests/player-exit.test.cjs`, vm-slice of the pure section)
- exitPlayer sets status/exitedAt/cashout; second call returns false; negative/NaN rejected.
- updateExitCashout only works on exited players.
- activePlayers/exitedPlayers partition.
- Regex: `normalize` includes `status` default; `buildHistoryEntry` copies `status`.
- A tableBalance slice test: exited cashout counts toward `out` (slice `function wholeMoney`…`function totals`).

### Checkpoint
Run full tests + diff check. Controller performs browser QA: add 3 players, rebuys, exit one with
cashout, verify no plus button, finish game, settlement prefilled, transfers correct, close, history
shows player with status.

## Task 2: Group data contracts, state collections, and adapters

**Goal 2:** the model supports registered/guest identities, former members, group and ungrouped games,
derived leaderboards, and a future backend — without changing the game engine or duplicating truth.

### State additions (all arrays default `[]` in `normalize()`, included in `remoteBody()` and in the
`applyRemote` equality comparison)
```
state.groups:       [Group]
state.groupMembers: [GroupMember]
state.invites:      [Invite]
state.friendships:  [Friendship]
state.leaderRef:    ParticipantRef | null        // current game: who started it
```
Contracts (JSDoc typedef comments at the top of the new section):
```
ParticipantRef = { userId: string|null, guestId: string|null, displayName: string }
Group       = { id, name, avatarDataUrl: string|null, createdBy: ParticipantRef, createdAt,
                archivedAt: ISO|null, deletedAt: ISO|null }
GroupMember = { id, groupId, userId: null, guestId, displayName, role: "admin"|"member",
                status: "active"|"left"|"removed", joinedAt, leftAt: ISO|null }
Invite      = { id, groupId, token, createdBy: ParticipantRef, createdAt, revokedAt: ISO|null }
Friendship  = { id, requester: ParticipantRef, addressee: ParticipantRef,
                status: "pending"|"accepted"|"rejected", createdAt, respondedAt: ISO|null }
```
Player (current game) gains `guestId: string|null`, `memberId: string|null` (null for ungrouped
games and legacy). `buildHistoryEntry` copies both. History entries gain `groupId`, `startedAt`,
`leaderRef` (copied from state at close; legacy entries: null).

### New-state helper (fixes a latent data-loss bug)
```
function newCurrentGame(base, patch)   // returns { ...base, example:false, phase, gameId:newId(), players:[],
                                       //   settlementStatuses:{}, groupId:null, startedAt:null, leaderRef:null, ...patch }
                                       // preserving history, debts, groups, groupMembers, invites, friendships, updatedAt
```
Replace the hand-built objects in `markReal()`, `startUngroupedGame()`, and the reset button with it.
`markReal()` keeps `phase:"active"` + `startedAt: now`; `startUngroupedGame()` keeps its fields;
reset keeps `phase:"closed"`.

### Pure section `  // ---------- groups domain (pure) ----------` (after the player-exit section,
before `function el(`). Every function takes data in, returns data out; none touches `state`/DOM.
```
function normalizeGroup(g) / normalizeGroupMember(m) / normalizeInvite(i) / normalizeFriendship(f)
function identityKey(ref)                       // ref.userId ? "u:"+userId : ref.guestId ? "g:"+guestId : "n:"+displayName
function sameIdentity(a, b)
function resolveGuestId(collections, displayName)   // reuse existing guestId (groupMembers, history players) or newId()
function findMyMembership(members, groupId, meName)  // active member with displayName === meName
function isGroupAdmin(members, groupId, meName)
function activeMembers(members, groupId) / formerMembers(members, groupId)
function visibleGroups(groups)                  // !deletedAt && !archivedAt
function archivedGroups(groups)
function groupClosedGames(history, groupId)     // history entries with groupId, newest first
function gameWinners(historyEntry)              // players with max net (ties → all); [] if no players
function isLeaderboardEligible(participant, members)  // identity matches any member of the group (any status)
function buildLeaderboard(history, members, groupId) // → [LeaderboardEntry]; NO money fields
function getGroupSummary(collections, groupId, meName) // → GroupSummary
function getGroupSummaries(collections, meName)        // replaces the empty stub; visibleGroups → summaries
function canStartGroupGame(collections, groupId)       // { ok, reason: null|"group-archived"|"group-has-open-game"|"another-game-open" }
```
`collections` = `{ groups, groupMembers, history, currentGame: { gameId, phase, groupId, players, startedAt, example } }`
built by a tiny `collectionsOf(state)` helper (non-pure, next to `getActiveGameSummaries`).

Summary shapes (UI consumes only these):
```
GroupSummary     = { groupId, name, avatarDataUrl, memberCount, members: [displayName], hasActiveGame,
                     activeGamePhase, gameCount, lastGameAt, leaderNames: [displayName], isAdmin, isMember }
LeaderboardEntry = { rank, identityKey, displayName, gamesPlayed, wins, isFormerMember }   // no net!
GroupGameSummary = { gameId, at, startedAt, playerCount, playerNames, winnerNames, potSize, totalEntries,
                     isBalanced }                                                             // no per-player net
```
Ranking: total net desc, then gamesPlayed desc, then displayName. Ties in net share the same rank
number. `wins` = games where the player is in `gameWinners`.

### Other

- Existing `renderGroupCard` expects `memberCount/members/lastGame/gameCount/leader/topPlayers`;

- `renderGamesDashboard()` passes `getGroupSummaries(collectionsOf(state), me)`.

- identityKey precedence; resolveGuestId reuses by displayName.
- gameWinners: single, tie, empty.

- buildLeaderboard: ordering, tie rank, wins count, no money fields (assert `Object.keys` ∩

- Regex: `remoteBody` and `applyRemote` mention `groups`, `groupMembers`, `invites`, `friendships`.
